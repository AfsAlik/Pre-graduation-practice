# Инструкция по сборке и запуску системы «Финансовый помощник»

Документ объясняет, что лежит в репозитории, как запустить серверную часть и мобильное приложение
на своем компьютере, как повторить испытания и как пересобрать отчет. Команды приведены для Windows
(PowerShell) и для Linux/macOS; там, где они совпадают, приведен один вариант.

## 1. Что находится в репозитории

| Каталог или файл | Содержимое |
|---|---|
| `Отчет по преддипломной практике/` | Готовые документы: отчет (`.docx` и `.pdf`), заполненное индивидуальное задание, проект отзыва руководителя |
| `server/` | Серверная часть: серверное приложение (FastAPI), сервис машинного обучения, миграции БД, тесты, сценарии испытаний, файлы развертывания |
| `mobile/` | Мобильное приложение для Android (Kotlin, Jetpack Compose) – проект Android Studio |
| `tools/report/` | Средства формирования отчета: тексты разделов, генератор `.docx`, диаграммы, результаты испытаний |
| `Старые работы/`, `Указания по выполнению работы и шаблоны/` | Исходные материалы: прежние работы и указания преподавателя |
| `QUESTIONS.md` | Вопросы, заданные перед началом работы, и ответы на них |

Система состоит из двух частей. **Серверная часть** хранит данные пользователей, считает аналитику,
бюджет, портфель, рекомендации и принимает синхронизацию. **Мобильное приложение** работает с
локальной зашифрованной базой данных на телефоне и обменивается данными с сервером, когда есть связь.
Чтобы увидеть систему целиком, нужно запустить сервер (раздел 2), затем приложение (раздел 3).

## 2. Запуск серверной части

Есть два способа. Для знакомства с системой и показа приложения достаточно способа А – он требует
только Python. Способ Б повторяет состав рабочей установки (PostgreSQL, Redis, отдельный сервис
машинного обучения) и нужен, если требуется показать развертывание так, как оно описано в
руководстве администратора.

### Способ А. Быстрый запуск без Docker (рекомендуется для первого знакомства)

Что потребуется: Python 3.11–3.13 ([python.org](https://www.python.org/downloads/); при установке
в Windows отметить «Add python.exe to PATH»).

Windows (PowerShell):

```powershell
cd server
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run_local.py
```

Linux/macOS:

```bash
cd server
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run_local.py
```

Если PowerShell не разрешает выполнить `Activate.ps1`, выполните один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` либо используйте обычную командную строку
(`.venv\Scripts\activate.bat`).

Что происходит при запуске `run_local.py`:

1. Создается файл базы данных `server/var/local/finhelper.db` (СУБД SQLite – отдельная установка
   СУБД не нужна).
2. Обучается начальная модель автоматической категоризации операций (несколько секунд).
3. Загружаются курсы валют Банка России (нужен интернет; без интернета сервер продолжит работу,
   в журнале появится предупреждение; ключ `--offline` отключает обращение к внешним источникам).
4. При первом запуске создаются четыре демонстрационные учетные записи с данными за шесть месяцев.
5. Запускается сервер на порту 8000. Остановка – `Ctrl+C`. Повторный запуск – той же командой
   `python run_local.py`, данные сохраняются. Чтобы начать с чистой базы, удалите каталог
   `server/var/local`.

Проверка: откройте в браузере <http://localhost:8000/docs> – это интерактивное описание
программного интерфейса (все запросы можно выполнить прямо со страницы), а
<http://localhost:8000/health/ready> должен вернуть `{"status":"ok","database":true}`.

Демонстрационные учетные записи (пароль у всех `Demo-2026-pass`):

| Адрес | Роль | Что в ней есть |
|---|---|---|
| `user@example.com` | Пользователь | счета, операции за полгода, бюджеты, цели, регулярные платежи |
| `investor@example.com` | Пользователь | то же и инвестиционный портфель (акции, облигации, фонды, валюта) |
| `analyst@example.com` | Аналитик | доступ к показателям качества моделей и обучению |
| `admin@example.com` | Администратор | пользователи, журналы, мониторинг, настройки системы |

### Способ Б. Развертывание в Docker Compose (как в руководстве администратора)

Что потребуется: [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows, macOS)
или Docker Engine с подключаемым модулем Compose (Linux).

```bash
cd server
cp .env.example .env        # в PowerShell: Copy-Item .env.example .env
```

Откройте `.env` и задайте как минимум `POSTGRES_PASSWORD` и `FH_SECRET_KEY` (любая длинная случайная
строка). Назначение остальных параметров описано в руководстве администратора (раздел 4.1 отчета).
Затем:

```bash
docker compose up -d --build
docker compose ps
docker compose exec api python -m app.manage seed-demo
```

Первая сборка занимает 5–10 минут (скачиваются образы и библиотеки). Команда `docker compose ps`
должна показать состояние `healthy` у контейнеров `db`, `redis`, `ml`, `api`. Третья команда создает
демонстрационные учетные записи (см. таблицу выше). Состав установки:

| Контейнер | Назначение |
|---|---|
| `db` | СУБД PostgreSQL 16 |
| `redis` | кеш и очередь фоновых задач |
| `ml` | сервис машинного обучения (категоризация, прогноз) |
| `api` | серверное приложение; при запуске само применяет миграции БД |
| `worker` | фоновые задачи: уведомления, обновление курсов и котировок, резервное копирование |
| `prometheus`, `grafana` | мониторинг; запускаются командой `docker compose --profile monitoring up -d` |

Полезные команды:

```bash
docker compose logs -f api                      # журнал серверного приложения
docker compose exec worker scripts/backup.sh    # резервная копия вне расписания
docker compose down                             # остановить (данные сохраняются)
docker compose down -v                          # остановить и удалить все данные
```

> Важно. В среде, где готовилась работа, не было службы Docker, поэтому файл `docker-compose.yml`
> проверен только командой `docker compose config`, а сами контейнеры не запускались: те же
> компоненты (PostgreSQL 16, Redis, серверное приложение, исполнитель задач, сервис машинного
> обучения) работали на стенде как обычные процессы. Если при первом запуске в Docker что-то пойдет
> не так, смотрите `docker compose logs` – и используйте способ А, он проверен полностью.

## 3. Сборка и запуск мобильного приложения

Что потребуется: [Android Studio](https://developer.android.com/studio) (актуальная версия; вместе
с ней ставятся JDK 17 и Android SDK). Отдельно ставить Gradle не нужно – проект содержит
Gradle Wrapper.

1. В Android Studio: **File → Open** → выбрать каталог `mobile`. Дождаться окончания синхронизации
   Gradle (при первом открытии скачиваются библиотеки, 5–15 минут). Если студия предложит
   установить недостающие компоненты SDK (Android 15, API 35) – согласиться.
2. Создать эмулятор: **Tools → Device Manager → Create Virtual Device**, например Pixel 7 с
   образом Android 14 или 15. Либо подключить телефон с Android 8.0 и новее с включенной
   отладкой по USB.
3. Запустить серверную часть (раздел 2) и нажать **Run ▶** в Android Studio.
4. На экране входа указать адрес сервера:
   - эмулятор Android Studio: `http://10.0.2.2:8000` (так эмулятор видит компьютер, на котором он
     запущен; это значение подставлено по умолчанию);
   - настоящий телефон: `http://<IP-адрес компьютера в домашней сети>:8000` (например
     `http://192.168.1.10:8000`; адрес показывает команда `ipconfig` в Windows или `ip addr` в
     Linux). Телефон и компьютер должны быть в одной сети Wi-Fi, а брандмауэр Windows должен
     разрешать входящие подключения к порту 8000.
5. Войти под демонстрационной учетной записью (`user@example.com` / `Demo-2026-pass`) или
   зарегистрировать новую.

Сборка из командной строки (нужен JDK 17 и переменная `ANDROID_HOME` либо файл
`mobile/local.properties` со строкой `sdk.dir=путь к Android SDK`; Android Studio создает этот
файл сама):

```bash
cd mobile
./gradlew assembleDebug        # в Windows: gradlew.bat assembleDebug
./gradlew testDebugUnitTest    # модульные тесты и снимки экранов (132 теста)
./gradlew lintDebug            # статический анализ Android Lint
```

При первом запуске тестов библиотека Robolectric скачивает образ Android (около 150 МБ). Есть и
проверка совместимости приложения с запущенным сервером – она выполняет через сетевой слой
приложения регистрацию, синхронизацию, импорт, экспорт и операции администратора:

```bash
./gradlew testDebugUnitTest -PliveServer=http://127.0.0.1:8000/ --tests "*LiveServerTest*"
```

Готовый установочный файл: `mobile/app/build/outputs/apk/debug/app-debug.apk`. Его можно
установить на телефон командой `adb install app-debug.apk` или просто скопировав на телефон.

Отладочная сборка разрешает соединение по HTTP без шифрования, чтобы работать с локальным
сервером. Сборка для публикации (`release`) допускает только HTTPS; для нее сервер должен стоять за
обратным прокси с сертификатом TLS (образец – `server/deploy/nginx.conf.example`).

Подробности о структуре проекта, настройке push-уведомлений (Firebase) и ограничениях – в
`mobile/README.md`.

## 4. Повторение испытаний

Все команды выполняются в каталоге `server` с активированным виртуальным окружением (раздел 2,
способ А). Дополнительные библиотеки для испытаний: `pip install -r requirements-dev.txt`.

| Что проверяется | Команда | Пояснение |
|---|---|---|
| Автоматизированные тесты сервера | `pytest` | 82 теста, СУБД SQLite в памяти; занимает около минуты |
| То же на PostgreSQL | задать `FH_TEST_DATABASE_URL=postgresql+psycopg://пользователь:пароль@localhost:5432/имя_тестовой_базы` и выполнить `pytest` | тестовая база должна существовать и быть пустой |
| Стиль исходного текста | `ruff check .` | |
| Сценарии испытаний по ПМИ | `python standcheck/run_checks.py --out result.json` | выполняется над запущенным сервером (по умолчанию `http://127.0.0.1:8000`), создает собственные тестовые учетные записи; ключ `--help` показывает параметры |
| Резервное копирование и восстановление | `python standcheck/check_backup.py --db-url <адрес рабочей базы> --restore-url <адрес пустой базы для восстановления>` | только для PostgreSQL; нужны утилиты `pg_dump` и `pg_restore`; сравнивает число строк и контрольные суммы таблиц исходной и восстановленной баз |
| Нагрузочные испытания | `python -m app.manage seed-load --users 200`, затем `locust -f loadtest/locustfile.py --headless -H http://127.0.0.1:8000 -u 100 -r 10 -t 30m` | имеет смысл только на PostgreSQL (способ Б или отдельная установка); обработка журнала – `python loadtest/analyze.py` |
| Тесты мобильного приложения | в каталоге `mobile`: `./gradlew testDebugUnitTest` | выполняются на компьютере, устройство не нужно |

Результаты испытаний, вошедшие в отчет, сохранены в `tools/report/results/` (файлы JSON), по ним
сформированы подраздел 3.6 и приложение Б отчета.

### Что не удалось проверить и что стоит проверить на своем телефоне

Испытания проводились в среде без устройств Android и без эмулятора, поэтому часть проверок ПМИ
перенесена в «Перечень необходимых доработок» протокола (приложение Б). Если есть телефон или
эмулятор, перед защитой полезно пройти короткий список – он же пригодится для демонстрации:

1. Приложение устанавливается и запускается; регистрация, вход, выход.
2. Добавление расхода и дохода, перевод между счетами; баланс на главном экране меняется.
3. Режим «в самолете»: добавить операцию без сети → включить сеть → операция появляется на сервере
   (видно на странице `/docs` запросом `GET /api/v1/transactions` или во второй установке приложения).
4. Бюджет: задать лимит, превысить 80 % и 100 % – приходит уведомление.
5. Цель накопления: взнос, прогноз срока.
6. Портфель: добавить сделку (например, SBER), обновить котировки.
7. Отчеты и экспорт; рекомендации и оценка рекомендации.
8. Быстрый ввод: голосовая фраза («потратил 500 рублей на кафе») и фотография чека. Включенная в
   приложение модель распознавания понимает только латиницу и цифры, поэтому сумма чека
   определится, а название магазина, набранное кириллицей, придется ввести вручную.
9. Темная тема, крупный шрифт, TalkBack – для проверки требований доступности.
10. Уведомление на телефоне о превышении лимита (при первом запуске приложение спросит разрешение
    на показ уведомлений).

Все, что получится подтвердить, можно перенести из перечня доработок в результаты испытаний.

## 5. Пересборка отчета

Нужна только если меняются тексты или результаты. Требуются Python с библиотеками `python-docx` и
`pillow`, LibreOffice (для получения PDF и номеров страниц оглавления) и, для перерисовки диаграмм,
Node.js с Playwright.

```bash
cd tools/report
python results_text.py      # подраздел 3.6 из файлов результатов
python build_report.py      # отчет .docx и .pdf в каталоге «Отчет по преддипломной практике»
python diagrams.py && node render.js   # только при изменении диаграмм
```

Тексты разделов лежат в `tools/report/content/*.md` в простой разметке (заголовки `#`, списки `- `,
таблицы и рисунки – директивы `!table` и `!figure`); оформление по ГОСТ 7.32-2017 и шаблону
преподавателя задается в `docx_kit.py`. Готовый `.docx` можно править и вручную в Word – но тогда
при следующей пересборке ручные правки будут потеряны.

После правок в Word обновите оглавление (щелчок правой кнопкой по оглавлению → «Обновить поле»),
если менялись заголовки или объем.

## 6. Частые вопросы

**Порт 8000 занят.** Запустите `python run_local.py --port 8080` и укажите этот порт в адресе
сервера в приложении.

**Приложение пишет, что сервер недоступен.** Проверьте с телефона или эмулятора в браузере адрес
`http://<адрес>:8000/health`. Если страница не открывается – дело в сети или брандмауэре, а не в
приложении.

**Курсы валют или котировки не загружаются.** Сервер обращается к сайтам Банка России
(`www.cbr.ru`) и Московской биржи (`iss.moex.com`). Без доступа к ним система продолжает работать
с последними сохраненными значениями и помечает их как устаревшие.

**Письма и push-уведомления не приходят.** По умолчанию они записываются в журнал сервера
(`FH_EMAIL_PROVIDER=log`, `FH_PUSH_PROVIDER=log`). Для настоящей отправки нужны почтовый сервер
(SMTP) и проект Firebase – параметры описаны в руководстве администратора.

**Подтверждение адреса электронной почты при регистрации.** В быстром запуске отключено. В Docker
управляется параметром `FH_REQUIRE_EMAIL_CONFIRMATION`; ссылка подтверждения при `log`-режиме почты
печатается в журнале `docker compose logs api`.
