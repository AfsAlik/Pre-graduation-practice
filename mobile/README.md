# Мобильное приложение «Финансовый помощник» (Android)

Клиентская часть системы управления личными финансами: учет доходов и расходов, бюджет, финансовые цели,
инвестиционный портфель, отчеты, рекомендации и административный модуль. Приложение работает без подключения
к сети: данные хранятся в зашифрованной локальной базе и синхронизируются с серверной частью (`../server`).

## 1. Что потребуется

| Средство | Версия |
|---|---|
| Android Studio | Narwhal 2025.1.1 или новее (поддержка Android Gradle Plugin 8.11) |
| JDK | 17 или 21 (подойдет встроенный в Android Studio JetBrains Runtime) |
| Android SDK | Platform 35 (Android 15), Build-Tools 35.0.0 |
| Устройство или эмулятор | Android 8.0 (API 26) и выше |

Gradle устанавливать не нужно: в проекте есть Gradle Wrapper (`gradlew`, версия Gradle 8.14.3).
Версии библиотек заданы в одном файле – `gradle/libs.versions.toml`
(Kotlin 2.1.21, Compose BOM 2025.06.01, Room 2.7.2, Retrofit 2.11.0, SQLCipher 4.9.0).

## 2. Открытие и сборка

1. В Android Studio: **File → Open** → выбрать каталог `mobile`. Дождаться окончания синхронизации Gradle
   (при первом открытии загружаются библиотеки, нужен доступ в Интернет).
2. Файл `local.properties` с путем к Android SDK Android Studio создаст сама. При сборке из командной строки
   создайте его вручную: `sdk.dir=C\:\\Users\\<имя>\\AppData\\Local\\Android\\Sdk` (Windows) или
   `sdk.dir=/home/<имя>/Android/Sdk` (Linux).
3. Сборка из командной строки (в каталоге `mobile`; в Windows вместо `./gradlew` использовать `gradlew.bat`):

```
./gradlew assembleDebug        # отладочная сборка: app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # модульные тесты (JVM, без эмулятора)
./gradlew lintDebug            # статический анализ; отчет: app/build/reports/lint-results-debug.html
```

## 3. Запуск вместе с локальным сервером

Сначала запустите серверную часть (см. `../server`), по умолчанию она слушает порт 8000.
Адрес сервера задается на экране входа: ссылка **«Указать адрес сервера»** → поле **«Адрес сервера»**.
Адрес сохраняется на устройстве.

### На эмуляторе

1. **Device Manager → Create Device** (например, Pixel 7, образ API 35) и запустить эмулятор.
2. Нажать **Run ▶** (конфигурация `app`).
3. Адрес сервера менять не нужно: в отладочной сборке по умолчанию используется `http://10.0.2.2:8000/` –
   так эмулятор обращается к компьютеру, на котором он запущен.

### На реальном телефоне

1. На телефоне включить «Параметры разработчика» и «Отладку по USB», подключить его кабелем, выбрать в списке устройств.
2. Телефон и компьютер должны быть в одной сети Wi-Fi. Сервер должен принимать подключения из сети:
   запуск с параметром `--host 0.0.0.0`, порт 8000 открыт в брандмауэре.
3. Узнать адрес компьютера в сети (`ipconfig` в Windows, `ip addr` в Linux), например `192.168.1.10`.
4. На экране входа указать адрес сервера `http://192.168.1.10:8000/`.

Протокол HTTP разрешен только в отладочной сборке (`app/src/debug/res/xml/network_security_config.xml`).
Выпускаемая сборка (`release`) работает только по HTTPS; адрес по умолчанию задается полем
`DEFAULT_BASE_URL` в `app/build.gradle.kts`.

### Первый вход

Зарегистрируйте учетную запись на экране «Регистрация» (если на сервере включено подтверждение адреса,
перейдите по ссылке из письма либо создайте учетную запись средствами сервера). Административное меню
появляется в боковом меню главного экрана у пользователей с ролью «Аналитик» или «Администратор».

## 4. Тесты и снимки экранов

Все тесты выполняются на JVM (JUnit 4 и Robolectric), эмулятор не нужен:

```
./gradlew testDebugUnitTest
```

Проверяются: очередь и синхронизация с имитацией сервера (применение, повтор, конфликт, отклонение,
отсутствие дублирования после обрыва связи), запросы к базе Room (в памяти), бизнес-правила ввода данных,
расчет бюджета, целей и портфеля, разбор голосовой фразы и текста чека, форматирование сумм, сетевой слой
(обновление токена, коды ошибок), построение состояния экранов.

Совместимость с настоящим сервером проверяет тест `LiveServerTest` (по умолчанию пропускается). Он
регистрирует пользователя, синхронизирует записи всех видов и обращается к разделам, работающим через
сервер. Сервер должен быть запущен и допускать регистрацию без подтверждения адреса
(`FH_REQUIRE_EMAIL_CONFIRMATION=false`); для разделов администратора задаются переменные окружения
`LIVE_ADMIN_EMAIL` и `LIVE_ADMIN_PASSWORD`:

```
./gradlew testDebugUnitTest -PliveServer=http://127.0.0.1:8000/ --tests "*LiveServerTest*"
```

Снимки экранов для руководства пользователя формируются тестом `ScreenshotTest` (Roborazzi – отрисовка
настоящих экранов Compose на JVM) по демонстрационным данным из `DemoData.kt`:

```
./gradlew testDebugUnitTest -Pscreenshots --tests "*ScreenshotTest*"
```

С ключом `-Pscreenshots` файлы PNG записываются в каталог `mobile/screenshots`, без него –
в `app/build/outputs/screenshots`. При первом запуске Robolectric загружает образ Android (около 150 МБ).

## 5. Push-уведомления (Firebase Cloud Messaging)

Приложение собирается и работает без Firebase: уведомления о бюджете, целях и регулярных платежах
формируются на устройстве, а уведомления сервера загружаются при синхронизации.
Чтобы включить доставку push-уведомлений сервера:

1. Создать проект в консоли Firebase и добавить в него приложение Android с именем пакета `ru.finhelper.app`.
2. Из параметров проекта (или из файла `google-services.json`) взять четыре значения и записать их в
   `gradle.properties` либо в `~/.gradle/gradle.properties`:

```
fcmProjectId=<project_id>
fcmApplicationId=<mobilesdk_app_id, вида 1:1234567890:android:abc123>
fcmApiKey=<current_key>
fcmSenderId=<project_number>
```

3. Пересобрать приложение. Файл `google-services.json` и плагин Gradle `google-services` не нужны:
   Firebase инициализируется в коде (`notify/PushService.kt`). После входа устройство передает
   токен серверу (`POST /profile/devices`); на сервере должен быть настроен поставщик push-уведомлений.

## 6. Структура проекта

```
mobile/
├── gradle/libs.versions.toml      версии библиотек и модулей Gradle
├── app/build.gradle.kts           параметры сборки приложения
├── app/src/main/
│   ├── AndroidManifest.xml
│   ├── res/values/strings*.xml    тексты интерфейса (русский язык)
│   └── java/ru/finhelper/app/
│       ├── FinHelperApp.kt, MainActivity.kt   класс приложения и единственная активность
│       ├── di/           контейнер зависимостей (AppContainer)
│       ├── core/         деньги, даты, идентификаторы
│       ├── domain/       расчеты: бюджет, цели, портфель, отчеты, разбор чека и голосовой фразы
│       ├── data/local/   база данных Room (сущности, запросы), шифрование SQLCipher
│       ├── data/prefs/   настройки и защищенное хранилище токенов (Android Keystore)
│       ├── data/remote/  программный интерфейс сервера (Retrofit), модели, обработка ошибок
│       ├── data/sync/    очередь операций, синхронизация, фоновая задача WorkManager
│       ├── data/repo/    репозитории: учетные данные, профиль, вход, файлы, рекомендации
│       ├── notify/       уведомления: локальные правила, уведомления сервера, FCM
│       └── ui/           экраны Jetpack Compose
│           ├── theme/, components/, navigation/
│           ├── auth/           онбординг, вход, регистрация, восстановление пароля
│           ├── dashboard/      главный экран
│           ├── transactions/   транзакции, форма транзакции, счета, категории, шаблоны, платежи, корзина
│           ├── budget/, goals/, investments/, reports/, recommendations/
│           ├── profile/        профиль, уведомления, безопасность, справка
│           └── admin/          административный модуль
├── app/src/debug/                 разрешение HTTP для отладочной сборки
├── app/src/test/                  модульные тесты и формирование снимков экранов
└── screenshots/                   снимки экранов для руководства пользователя
```

Каждый экран состоит из двух функций: `…Route` получает состояние из модели представления (ViewModel),
а `…Screen` только отображает переданное состояние. Благодаря этому экраны отрисовываются в тестах
без базы данных и сети.

## 7. Как устроена работа без сети

- Единственный источник данных для экранов – локальная база Room, зашифрованная SQLCipher (AES-256).
  Ключевая фраза создается случайно и хранится зашифрованной ключом из Android Keystore.
- Каждое изменение сразу записывается в базу и в очередь несинхронизированных операций (в одной транзакции).
- Очередь отправляется запросом `POST /api/v1/sync` при изменении данных, при восстановлении связи
  (пока приложение открыто) и фоновой задачей WorkManager (когда приложение закрыто).
- Если сервер отклонил операцию (конфликт или нарушение правила), на устройство загружается версия сервера,
  а пользователь получает сообщение.
- Индикатор под заголовком каждого экрана показывает режим («Онлайн» / «Офлайн») и число операций в очереди.

## 8. Что не проверено на устройстве

Сборка и тесты выполнялись без эмулятора и без реального устройства, поэтому на устройстве необходимо
проверить вручную: запуск и время холодного старта, работу камеры и распознавание чека (ML Kit),
голосовой ввод, показ уведомлений и получение push-уведомлений FCM, фоновую синхронизацию WorkManager,
открытие зашифрованной базы SQLCipher, системные диалоги выбора и сохранения файлов (импорт выписки,
экспорт отчетов), работу с программами экранного доступа (TalkBack), обмен с настоящим сервером.
